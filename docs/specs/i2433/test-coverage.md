# Acceptance-criteria test coverage

AI-generated by Codex on behalf of Peter Palaga.

The baseline had no test configuring `vertx.http-versions`.
Existing tests covered legacy HTTPS HTTP/2, keep-alive, TLS, authentication, redirects and large SOAP messages,
but did not establish the ordered-list contract or bodyless preflight behavior.
The new tests assert the specification, including behavior not implemented on this branch.
They are intentionally enabled and may fail until the implementation catches up.

## Coverage map

- **AC1:**
  Existing coverage: No ordered-list tests.
  Added coverage: `HttpVersionsConfigTest`: singles, order, immutable lists, invalid tokens, duplicates, legacy
  conflicts, absent/empty binding, and a programmatically present empty list.
  Diagnostics must name the client and canonical property.

- **AC2:**
  Existing coverage: Legacy version selection only.
  Added coverage: `OrderedHttpVersionsTest`: both contextual overrides, conflicting policy, unsupported conduit at
  initialization, and equivalent legacy overrides.

- **AC3:**
  Existing coverage: Large requests existed, without preflight observations.
  Added coverage: `plaintextSelectionAndReuse`: a TCP recorder observes the upgrade request and subsequent HTTP/2
  preface; the peer verifies 100,000-character SOAP payloads, versions, invocation counts and connection reuse.

- **AC4:**
  Existing coverage: No refusal/preflight response distinction.
  Added coverage: Refusing peers for `2,1.1`, `2,1.1,1.0` and `2,1.0,1.1`; distinct preflight response, HTTP/1.1 SOAP
  response, no extra invocation or preflight.

- **AC5:**
  Existing coverage: No explicit prior-knowledge contract.
  Added coverage: Direct HTTP/2 preface and successful SOAP; rejection by an HTTP/1-only peer without an HTTP/1 SOAP
  request.

- **AC6:**
  Existing coverage: `KeepAliveTimeoutTest` covers legacy versions.
  Added coverage: Plaintext and TLS matrices, HTTP/1-first lists, plaintext rejection of `2,1.0`, HTTPS acceptance,
  and versions observed on incoming requests.

- **AC7:**
  Existing coverage: `ClientHttp2Test` covers legacy TLS HTTP/2.
  Added coverage: HTTP/2 and HTTP/1.1 ALPN peers, no-ALPN fallback, strict HTTP/2 failure, and ClientHello ALPN order
  decoding, including reversed preference.

- **AC8:**
  Existing coverage: `ClientHttp2Test`, `KeepAliveTimeoutTest`, `CertReloadTest`, `TlsConfigurationTest`,
  `ClientAuthRedirectTest`, and integration authentication/redirect tests.
  Added coverage: Legacy defaults, named-client independence, reuse, client recreation, TLS reload notification,
  destination changes, redirects, proxy/authentication and customizer preservation with explicit lists.

- **AC9:**
  Existing coverage: `LargeSlowTest`/`LargeSlowIT`, TLS and mTLS integration tests.
  Added coverage: Real-peer tests use large chunked SOAP requests and reject an untrusted TLS peer;
  `HttpVersionsTest`/`HttpVersionsIT` exercise selection and large SOAP requests in JVM/native applications.
  Parsed-list immutability has a direct assertion.

- **AC10:**
  Existing coverage: Configuration reference exists; migration guidance is incomplete.
  Added coverage: Manual documentation review below; no brittle prose-matching unit test.

- **AC11:**
  Existing coverage: Legacy HTTP/2, but no preflight assertions.
  Added coverage: Upgrade/refusal with `version=2` and both legacy overrides, large payloads, exactly-once SOAP,
  reuse, no preflight for legacy HTTP/1 clients or HTTPS.

The protocol tests use real Vert.x servers behind a TCP recorder, without mocks.
The recorder verifies that the bytes immediately following the `OPTIONS` headers start the HTTP/2 preface
or the HTTP/1.1 SOAP request, excluding a SOAP body in the preflight.
The TLS tests inspect the client's advertised ALPN protocols independently of the negotiated request version.
For reversed preference, either permitted server-selected protocol is accepted.

The present-empty-list test uses a real SmallRye configuration mapping with a Java default method returning
`Optional.of(List.of())`.
This distinguishes a present empty collection from an empty property, which SmallRye binds as absent.

HTTP/1.0 fixtures disable chunking because HTTP/1.0 does not support chunked transfer encoding.
Other large-request fixtures retain the normal chunking behavior.
TLS reload coverage combines the existing certificate-rotation tests with a new explicit-list reload-notification test;
the latter reloads the configured trust store and opens a connection to a second TLS peer.
The native tests cover the selection/large-payload smoke matrix; detailed wire recording remains in the JVM tests.

## Documentation and implementation review

The generated configuration reference uses the canonical name and describes ALPN, preflight,
prior knowledge and the lack of HTTP/1.0 retry.
It does not yet fully describe the rejected plaintext `2,1.0` combination or the legacy preflight change.
The 4.0.0 release notes do not yet provide migration examples for this feature.
AC10 remains a documentation implementation task.

`CXFClientInfo.parseHttpVersions()` returns immutable lists.
Its diagnostics still use `vertx.versions`, which the new configuration tests reject.
`HttpClientPool` still consumes a single version rather than the explicit list.
The test changes introduce no production negotiation, buffering or retry implementation.

## Focused commands

Run the configuration and real-peer tests:

```shell
mvnd -f extensions/core/deployment/pom.xml test -Dtest=HttpVersionsConfigTest,OrderedHttpVersionsTest
```

Run the existing regressions:

```shell
mvnd -f extensions/core/deployment/pom.xml test -Dtest=ClientHttp2Test,KeepAliveTimeoutTest
```

Run the JVM application tests:

```shell
mvnd -f integration-tests/client-server/pom.xml test -Dtest=HttpVersionsTest
```

Run the native application tests:

```shell
mvnd -f integration-tests/client-server/pom.xml verify -Pnative -Dquarkus.native.container-build \
  -Dtest=foo -Dsurefire.failIfNoSpecifiedTests=false -Dit.test=HttpVersionsIT
```

Run these commands sequentially because the Quarkus fixtures share default test ports.
